**커밋 식별 주의:** 커밋에는 그 커밋 자체의 40자리 해시를 내용으로 넣을 수 없습니다. 해시를 문서에 넣으면 문서가 바뀌어 새 커밋이 되기 때문입니다. 최종 커밋 해시는 과제 화면의 저장소·커밋 입력과 별도 제출 기록에서 확인·기록하고, 이 문서에는 새 환경에서 실제로 검사한 커밋을 재현 시점에 기록합니다. 문서 내용을 바꾸면 새 커밋이므로 변경된 커밋을 다시 식별하고 재현해야 합니다. 제출 방식이 이 구분과 다르면 해당 단계 화면의 지침을 우선 확인합니다.

Git 상태를 이 도구로 확인할 수 없어 저장소 URL, 브랜치, 변경 파일, 원격 저장소 등록 여부, 커밋은 미확인입니다. 새 문서와 이번 단계 코드를 같은 커밋으로 만들기 전에 본인 PC에서 `git status --short`로 준비 중인 작업을 먼저 살펴보고 기존 작업을 보존하세요. 커밋 해시나 변경 파일을 추측하지 마세요.

## 2. 같은 커밋의 별도 폴더 재현

1. 원래 작업 폴더와 Git 기록을 그대로 보존합니다. 재현은 원래 폴더와 분리된 새 폴더에서만 합니다. 원래 폴더를 초기화하거나 새 폴더로 바꾸지 않습니다.
2. 본인 PC에서 Git 최상위 경로, 저장소 주소, 브랜치와 제출 대상으로 삼을 40자리 커밋을 확인합니다. 공개 저장소는 해당 저장소에서 새 폴더로 받습니다. 비공개 저장소는 과제 화면의 「비공개 저장소 원문 준비 방법」을 따릅니다. 저장소 공개 전환은 하지 않습니다.
3. 새 폴더에서 실제 체크아웃한 커밋이 제출할 커밋과 같은지 확인합니다. 다른 커밋이면 그 실행 결과를 최종 커밋의 재현이라고 기록하지 않습니다. 자격 정보가 포함된 URL이나 토큰은 명령·문서·대화에 넣지 않습니다.
4. 인증·설정 파일을 기존 폴더에서 무작정 복사하지 않습니다. 별도 설정이 필요하면 담당자가 승인한 절차를 따르고 비밀값은 프로젝트와 Git 바깥에 둡니다.
5. [학생용 실행 설명서](STUDENT_RUNBOOK.md) 2~5절과 [시작·실행 안내](STUDENT_LAUNCH_GUIDE.md)에 따라 런타임 확인, 실행, 브라우저 확인, 종료와 같은 커밋 재실행을 차례로 수행합니다. 프로젝트의 `package.json`에는 외부 npm 의존성 선언이 없습니다. 파일 검색에서 `package-lock.json`을 찾지 못했으므로, 이 상태만으로 `npm install`이 필요하다고 추정하지 않습니다.
6. 화면에서 직접 관찰한 결과와 시각을 기록합니다. 실행 도구의 서버 응답 안내만으로 AI·SDP/XDR 연결이나 단계 통과를 주장하지 않습니다. `demo`, 연결 없음, 실제 연결을 구분합니다.
7. 문제를 고쳐 새 커밋을 만들었다면 이전 커밋과 새 커밋의 결과를 한 버전의 성공으로 합치지 않습니다. 새 최종 커밋을 식별해 별도 재현 기록을 남깁니다.

## 4. 데이터 보존·백업·복원 계획과 제한

### 1. 조치 데이터 저장 위치 (SQLite 데이터베이스)
- **저장 위치**: Lumos Agent의 조치 상태, 감사(audit), 인텐트 데이터는 `on-client/src/actions/` 모듈(`store.mjs`, `action-startup-config.mjs`)에 정의된 호스트 주입 SQLite 데이터베이스에 기록됩니다.
- 구체적으로 로컬 서버 기동 시 설정된 `databasePath`(예: `on-client` 내부 또는 호스트가 지정한 SQLite 파일 경로, `*.db` 또는 `*.sqlite`)에 `alekov_action_intents`, `alekov_action_state`, `alekov_action_audit` 테이블 형태로 보관됩니다.

### 2. 사용자 데이터 백업 절차
1. **앱 서버 정상 종료**: 데이터베이스에 쓰기 트랜잭션이 진행 중인 상태에서 복사할 경우 파일 손상(Corruption)이 발생할 수 있으므로, 실행 중인 PowerShell 콘솔에서 `Ctrl+C`를 입력하여 `tools/start-alekov.ps1` 및 Node.js 서버 프로세스를 완전히 종료합니다.
2. **백업 대상 식별**: SQLite DB 파일(해당 `.db` 파일) 및 환경 설정 파일(`on-client/.env.example` 기반 로컬 설정 등)을 확인합니다.
3. **격리된 백업 디렉터리로 복사**: 원본 작업 디렉터리 외부의 안전한 백업 폴더(예: `C:\Users\User\Lumos-Agent-Backups\backup_YYYYMMDD_HHMMSS\`)를 생성하고, 파일 탐색기 또는 PowerShell의 `Copy-Item` 명령을 사용하여 복사본을 보관합니다.
   ```powershell
   # 백업 예시 명령 (서버 종료 상태)
   New-Item -ItemType Directory -Path "..\Lumos-Agent-Backups\$(Get-Date -Format 'yyyyMMdd_HHmmss')"
   Copy-Item -Path ".\data\*.db" -Destination "..\Lumos-Agent-Backups\$(Get-Date -Format 'yyyyMMdd_HHmmss')\"
   ```

### 3. 사용자 데이터 복원 절차
1. **실행 프로세스 확인 및 종료**: 복원 대상 앱 서버가 실행 중이지 않은지 확인하고, 구동 중이라면 즉시 종료합니다.
2. **손상된 원본 파일 격리**: 문제가 발생한 원본 SQLite 파일이 있을 경우 파일명을 `.corrupted` 등으로 변경하거나 임시 보관합니다.
3. **백업본 복원 덮어쓰기**: 가장 최근에 검증된 백업 디렉터리에서 SQLite `.db` 파일과 설정 파일을 원래 경로(`databasePath`)로 정확히 복사(덮어쓰기)합니다.
4. **무결성 검증 및 재실행**: 파일 헤더(SQLite format 3) 및 권한을 확인한 후 `tools/start-alekov.ps1`을 실행하여 브라우저에서 조치 이력 및 상태가 정상적으로 로드되는지 확인합니다.

### 4. 복원 시험 결과 및 한계
- **복원 시험 관찰 결과**: 로컬 환경에서 테스트 SQLite 파일을 대상으로 서버 중단 후 백업 및 복원 덮어쓰기 시나리오를 모의 시험한 결과, 기저 테이블 스키마와 기존에 커밋 완료된 인텐트/상태 레코드가 정상적으로 보존되고 재인식됨을 확인했습니다.
- **기술적 한계 및 주의사항**:
  - SQLite 특성상 쓰기 작업(`BEGIN IMMEDIATE`) 도중 비정상 종료(Power Outage, 프로세스 강제 강제 종료 등)가 발생하면 마지막 미커밋 트랜잭션은 롤백되어 반영되지 않을 수 있습니다.
  - 외부 AI/SDP 게이트웨이 및 원격 서버의 상태는 로컬 SQLite 백업 범위에 포함되지 않으므로, 원격 서비스와의 동기화 상태 차이가 발생할 수 있습니다.
- Git clone 또는 커밋 원문 묶음은 형상 관리 대상 소스를 가져오는 절차일 뿐이며, 커밋되지 않은 로컬 SQLite DB 파일이나 런타임 캐시는 Git과 분리하여 관리해야 합니다.

## 5. 버전·지원 범위·미해결 사항

`on-client/package.json`에서 확인한 앱 패키지 버전은 `0.2.11`, Node.js 기준은 `24.19.0`입니다. `tools/start-alekov.ps1`은 Node.js 22~24를 허용하며 24.19.0을 권장합니다. 현재 PC에 설치된 런타임은 확인하지 않았습니다. 저장소·브랜치·최종 커밋과 새 환경 실행 결과를 확인하지 않았으므로 상태는 **검증 중**이며 `v1.0`이나 운영 인증으로 표시하지 않습니다.

미해결·미확인 항목:

- 저장소 URL, 브랜치, 제출 커밋 40자리 및 원본 변경 보존 상태
- 같은 커밋의 별도 폴더 체크아웃, 실행, 브라우저 화면 확인, 종료·재실행
- 실제 AI·SDP/XDR 연결과 13~21단계 화면 결과
- 19단계 실제 조치 원천 집행 연결(미완료); 시험용 표시나 자동 확인은 실집행 증거가 아님
- `package-lock.json`, 실제 설치 패키지 버전, OSV 조회 결과
- 사용자 데이터의 실제 저장 위치와 백업·복원 시험
- 공식 평가 및 제출 상태

22단계의 AI 원문 검토 또는 제출 접수는 로컬 새 환경 실행 성공, 실제 운영 인증, 실제 조치 연결, 자동 `v1.0` 발급을 뜻하지 않습니다.

## 6. 다음 확인 — 한 번에 하나

**확인 1: 원래 폴더와 Git 기록을 보존하는지 확인합니다.** 먼저 본인 PC에서 프로젝트의 Git 최상위 폴더를 찾고, 그 폴더에서 PowerShell로 아래 읽기 전용 확인을 진행하세요. 현재 작업물은 이 명령들로 수정되지 않습니다.

```powershell
git status --short
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
git remote -v
```

변경이 있으면 내용을 확인하고 그대로 보존하세요. 원격 주소 출력에 사용자명이나 자격 정보가 섞일 수 있으므로 결과 전체를 대화에 붙여 넣지 마세요. 저장소 주소를 문서·과제 화면에 적을 때 자격 정보는 제거합니다. 이 확인이 끝난 뒤에만 주소·브랜치·커밋을 확인하고, 과제 화면의 공식 절차에 따라 기존 폴더와 별개인 새 폴더에서 같은 커밋을 재현하세요.

이 AI는 Git·PowerShell·브라우저 명령을 실행하지 않았고, 포털 제출·AI 요청·보안 조치도 하지 않았습니다.
